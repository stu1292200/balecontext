## Answer: run1-hook.answer.md

`merge_setting` no longer drops keys set to `None`, which is the cause. I haven't run anything, including the new test.

**Cause:** `merge_setting` in `src/requests/sessions.py:76-99` merged the session and request dicts but never removed keys whose value is `None`. A `None` on the request overrode the session's value and stayed in the result. It was then either sent as-is or dropped later, so the session's header was not removed. `Session.prepare_request` (`src/requests/sessions.py:541-544`) uses it for headers and params, and `Session.merge_environment_settings` (`src/requests/sessions.py:857`) uses it for proxies.

**Changes:**
- **`src/requests/sessions.py:99-103`:** after the merge, `merge_setting` collects the keys whose merged value is `None` and deletes them. The keys are collected first so the dict isn't changed while iterating.
- **`tests/test_requests.py:1764-1780`:** added `test_request_none_removes_session_setting`. It checks that `Accept-Encoding: None` on a request removes the session's header, that `params={"foo": None}` removes the session param, and that `{"http": None}` removes the session proxy. It builds the request without sending it.

The existing `test_header_remove_is_case_insensitive` (`tests/test_requests.py:1757-1762`) already covers header removal with `None`, so I left it as is. It would have failed before the fix.

## Answer: run1-without.answer.md

I fixed the cause in `merge_setting` and added three tests. I haven't run anything, so none of it is tested.

**Cause:** `merge_setting()` in `src/requests/sessions.py` (lines 96–99 before the edit) merged the request's settings over the session's with `update()` and returned the result. It never dropped keys whose value is `None`, so a request value of `None` replaced the session value but stayed in the merged dict. `Accept-Encoding: None` therefore didn't remove the session's header. `prepare_request` calls it for headers and params (`src/requests/sessions.py:541` and `:544`), and `Session.request` calls it for proxies (`:857`). All three had the same bug.

**Changes:**
- `src/requests/sessions.py:99-102`: after the merge, collect the keys whose value is `None` and delete them, before `return merged_setting`.
- `tests/test_requests.py:1764-1778`: the existing tests didn't cover this. `test_header_remove_is_case_insensitive` at line 1757 only covers the case-insensitive case. `test_headers_on_session_with_None_are_not_sent` at line 496 covers `None` set on the session, not on the request. I added three tests next to the first one:
  - `test_request_headers_none_removes_session_header`: `Accept-Encoding: None` on the request removes the session's header.
  - `test_request_params_none_removes_session_param`: a param set to `None` on the request is dropped.
  - `test_request_proxies_none_removes_session_proxy`: this calls `merge_setting` directly with proxy dicts.
