2. `signals.request_started.send(...)` (line 122). Receivers include `reset_queries` (`django/db/__init__.py:47-49`) and `close_old_connections` (`django/db/__init__.py:57-59`).
3. `request = self.request_class(environ)` (line 123) builds a `WSGIRequest` (`wsgi.py:57-80`).

   - It computes `path` (line 67) and `method` (line 71).
   - It parses the content type (line 73, `HttpRequest._set_content_type_params`, `django/http/request.py:156-170`).
   - It wraps `wsgi.input` in a `LimitedStream` (line 78).
4. `response = self.get_response(request)` (line 124) starts the Django-side handling.
5. After that returns:

## 1. Compile time: building the nodes

## 2. Render time: `ExtendsNode.render` (lines 134-160)

1. **Load the parent** (line 135): `get_parent` (lines 117-132):
   - It resolves `parent_name` against the context (line 118). An empty value raises `TemplateSyntaxError` (lines 119-125).
   - If the value is already a `Template`, or has a `.template` that is one, it is used directly (lines 126-131).
   - Otherwise `find_template` (lines 99-115) looks it up. It keeps a `history` of origins in `render_context` (lines 106-109) and passes it as `skip=` to `Engine.find_template` (`django/template/engine.py:155-163`, which loops over the template loaders). The `skip` list is what lets a template extend another template with the same name, so recursive extends works. The origin found is appended to the history (line 114).
2. **Create the shared block registry** (lines 137-139): `render_context[BLOCK_CONTEXT_KEY]` gets a `BlockContext` if it isn't already there. Its `blocks` is a `defaultdict(list)` of per-name queues (lines 15-17).
3. **Register this template's blocks** (line 142): `block_context.add_blocks(self.blocks)`. `add_blocks` (lines 22-24) does `insert(0, block)` for each name.
4. **Register the root's blocks** (lines 144-155):
   - It scans `compiled_parent.nodelist` for the first non-`TextNode` (lines 146-148).
   - If that node is *not* an `ExtendsNode`, the parent is the root template. All its `BlockNode`s are then added to the block context (lines 149-154).
   - If the parent itself extends another template, its own `ExtendsNode.render` does this registration when it runs.
5. **Render the parent** (lines 157-160): `compiled_parent._render(context)` (`django/template/base.py:166-167`, which calls `self.nodelist.render(context)`).
   - It is wrapped in `render_context.push_state(compiled_parent, isolated_context=False)` (`django/template/context.py:210-221`). This swaps `render_context.template` to the parent and restores it afterwards.
   - `isolated_context=False` means the render context is *not* pushed, so the `BlockContext` stays visible to the parent.
   - Calling `_render` rather than `render` keeps the same parser context (lines 157-158).

## 3. Block resolution: `BlockNode.render` (lines 51-69)

The block queues are ordered child first and ancestors after. Each `add_blocks` call inserts at the front, so the queue ends up with the root's block at the front and the most-derived child's block at the end. `pop()` takes from the end (lines 26-30), so the most-derived override is the one rendered.

- Line 52 fetches the `BlockContext` from `render_context`.
- Line 53 uses `with context.push():`, so variables set inside a block don't leak.
- **No block context** (lines 54-56): the template was rendered directly without `extends`. The block renders its own nodelist, with `context["block"] = self`.
- **With a block context** (lines 57-68):
  1. Line 58 `block_context.pop(self.name)` removes the most-derived override.
  2. If nothing is left, it falls back to `self` (lines 59-60).
  3. Lines 61-65 copy the block with `type(self)(block.name, block.nodelist)` and set `block.context = context`. This avoids storing context on a shared node, for thread safety. It then sets `context["block"]`.
  4. Line 66 renders that block's nodelist. `NodeList.render` (`django/template/base.py:1107-1108`) joins each node's `render_annotated` into a `SafeString`.
  5. Lines 67-68 push the popped block back (`BlockContext.push`, lines 32-33), so a sibling or repeated rendering of the same block still sees it.

## 4. `{{ block.super }}`: `BlockNode.super` (lines 71-83)

- It raises `TemplateSyntaxError` if `self.context` was never set, such as in a base template (lines 72-76).
- If the block context still holds a block for this name (the parent's version, since the child's was popped), it returns `mark_safe(self.render(self.context))` (lines 77-82). That renders the next block down the queue.
- Otherwise it returns `""` (line 83).

## End to end for `child.html` extending `base.html`
1. Rendering `child.html` runs its top-level `ExtendsNode.render`. The child's `{% block %}` tags are nested inside that node, so they are not rendered directly.
2. `base.html` is loaded, and the registry becomes `{name: [base_block, child_block]}`.
3. `base.html`'s nodelist renders. At each `{% block x %}`, `pop` returns the child's block if it overrides `x`, and otherwise the base's.
