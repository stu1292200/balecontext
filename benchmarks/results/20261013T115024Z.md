## Answer: run1-hook.answer.md

`Session` now has a `timeout` attribute that `Session.request()` uses when the call passes no timeout. I haven't run anything, including the new tests.

**Changes**
- `src/requests/sessions.py:423`: added the `timeout: _t.TimeoutType` annotation on `Session`.
- `src/requests/sessions.py:441`: added `"timeout"` to `Session.__attrs__`, so `__getstate__` and `__setstate__` pickle and restore it.
- `src/requests/sessions.py:492-495`: `__init__` sets `self.timeout = None`, with a doc comment.
- `src/requests/sessions.py:604-605`: the `timeout` parameter docstring in `request()` now says it defaults to `Session.timeout`.
- `src/requests/sessions.py:653-654`: `request()` does `if timeout is None: timeout = self.timeout`.
- `docs/user/advanced.rst:43-55`: a new paragraph and example in Session Objects.
- `docs/user/advanced.rst:1138-1140`: a short mention with a cross-reference in the Timeouts section.
- `tests/test_requests.py:1629-1657`: five new tests, placed right after `test_session_pickling`. They cover:
  - the default is `None`;
  - the session value is used when the call passes none;
  - a call's timeout overrides it;
  - with no session timeout, `send` gets `None`;
  - the value survives a pickle round trip.

**Limitation**
`None` means "not given", so `s.get(url, timeout=None)` can't switch off a session timeout; you have to set `s.timeout = None`. I wrote this into the docs at `docs/user/advanced.rst:53-54`.

**Old pickles**
A `Session` pickled before this change has no `timeout` in its state, so after unpickling it `request()` raises `AttributeError`. I didn't guard against that.
