## 2. Prepare it (`sessions.py:635`, `prepare_request` at `sessions.py:511-555`)
- The request's cookies are merged with the session's jar (`sessions.py:526-533`, `cookies.py:604-625`).

- `PreparedRequest.prepare` (`models.py:424-451`) runs these steps in order:
  1. method
  2. URL plus params
  3. headers
  4. cookies

  6. auth
  7. hooks

  Auth deliberately runs late so schemes like OAuth see the finished request, and hooks run after auth (`models.py:447-451`).

# Redirects and body reading in `Session.send()`

All paths are under `src/requests/`. Line numbers come from the excerpts BaleContext supplied. I didn't re-read the files, and no files were modified.

## Redirect handling in `send` (`sessions.py:752-829`)

1. **Pop the flag, keep the hooks.** `allow_redirects` is removed from `kwargs` (default `True`) so it never reaches the adapter (`sessions.py:773`). `stream` and the prepared request's hooks are saved at `sessions.py:774-775`.
2. **Send the first request.** `adapter.send` runs once and the elapsed time is recorded (`sessions.py:781-788`). Response hooks, then cookie extraction, run before any redirect logic (`sessions.py:791-799`). The first hop's cookies are stored before it is followed.
3. **Follow redirects** (`sessions.py:802-805`). It builds the generator `self.resolve_redirects(r, request, **kwargs)` and drains it with a list comprehension, so every hop is fetched eagerly. `history` holds the *subsequent* responses, not the original.
4. **Assemble history** (`sessions.py:810-815`). The original response is inserted at index 0 and the last response is popped as the result. The rest become `r.history`. The caller gets the final response, with every earlier hop in its history.
5. **Redirects disabled** (`sessions.py:818-824`). `resolve_redirects(..., yield_requests=True)` is asked for just the next `PreparedRequest`, which is stored in `r._next` (this backs `Response.next`). `StopIteration` means the response wasn't a redirect.

## What `resolve_redirects` does per hop (`sessions.py:186-307`)

- **Target.** `get_redirect_target` (`sessions.py:134-152`) returns the `Location` header, re-decoded as UTF-8, only if `resp.is_redirect`. The loop runs `while url` (`sessions.py:202-204`).
- **Copy and history.** It copies the prepared request and records `resp.history` (`sessions.py:205-209`).
- **Drain and cap.** It reads `resp.content` so the socket is released, falling back to `resp.raw.read(decode_content=False)` on decode errors (`sessions.py:211-214`). It raises `TooManyRedirects` once `len(resp.history) >= self.max_redirects` (`sessions.py:216-219`). It then calls `resp.close()` to return the connection to the pool (`sessions.py:222`).
- **URL.** It handles `//` scheme-relative URLs, carries over the previous fragment, joins relative `Location` values against `resp.url`, and percent-encodes (`sessions.py:225-245`).
- **Method.** `rebuild_method` is called (`sessions.py:247`). For anything except 307/308, it drops `Content-Length`, `Content-Type`, `Transfer-Encoding` and the body (`sessions.py:250-258`).
- **Cookies.** It removes the old `Cookie` header and rebuilds cookies from the response and session (`sessions.py:260-269`).
- **Proxies and auth.** `rebuild_proxies` and `rebuild_auth` run (`sessions.py:272-273`). Auth is stripped when the host changes.
- **Body rewind.** A rewindable body is rewound with `rewind_body` (`sessions.py:278-284`).
- **Re-send.** It calls `self.send(req, ..., allow_redirects=False, **adapter_kwargs)` (`sessions.py:292-301`). Passing `allow_redirects=False` stops the nested `send` from recursing, because the outer generator loops. It then extracts cookies and computes the next target (`sessions.py:303-307`).

## When the body is read

- **Adapter level: not read.** `HTTPAdapter.send` passes `preload_content=False, decode_content=False` to urllib3 (`adapters.py:703-704`). `build_response` keeps the raw stream in `response.raw` (`adapters.py:386`), so no body bytes have been consumed when `adapter.send` returns.
- **During redirects: always read, regardless of `stream`.** Each intermediate redirect response is drained with `resp.content` (`sessions.py:212`) before the next request, so the connection can be reused.
- **Final response:** `send` reads it with `r.content` only if `stream` is false (`sessions.py:826-827`).
  - **`stream=True`:** the body is left unread, and the caller must consume or close it.
  - **`allow_redirects=False`:** the same `stream` check applies to the single response. The response that is not followed is not drained by the redirect loop.
- **Nested sends:** each re-send inside `resolve_redirects` passes `stream=stream` (`sessions.py:294`). With `stream=False`, every hop's body is read inside its own `send` (`sessions.py:826-827`). The `resp.content` at `sessions.py:212` is then a cheap cached read. With `stream=True`, only the redirect hops are drained, and the last response stays streaming.

I didn't see the bodies of `rebuild_method`, `rebuild_proxies`, `rebuild_auth` or `rewind_body`. Their behavior above is inferred from their call sites and the visible outlines.

# Cookie flow: response to Session jar to next request

Paths are under `src/requests/`. This is based on the supplied excerpts and the earlier ones in this conversation. I didn't re-read the files, and no files were modified.

## 1. Saving response cookies

**Per-response jar** (`adapters.py:395`, `models.py:798`)
- `Response.__init__` creates an empty `response.cookies` jar (`models.py:798`).
- `HTTPAdapter.build_response` fills that jar with `extract_cookies_to_jar(response.cookies, req, resp)` (`adapters.py:395`).

**Extraction mechanics** (`cookies.py:135-150`)
- `extract_cookies_to_jar` returns early if the urllib3 response has no `_original_response` (`cookies.py:144-145`).
- Otherwise it wraps the request in a `MockRequest` (`cookies.py:147`, `cookies.py:45-49`) and the raw header message in a `MockResponse` (`cookies.py:149`, `cookies.py:121-126`). These adapters make the objects look like what `http.cookiejar` expects.
- `jar.extract_cookies(res, req)` then applies the cookiejar's policy and stores the `Set-Cookie` values (`cookies.py:150`).

**Session jar** (`sessions.py:794-799`, `sessions.py:303`)
- `Session.send` copies the cookies into `self.cookies` with `extract_cookies_to_jar(self.cookies, request, r.raw)` (`sessions.py:799`).
- It does the same for any hook-created history first (`sessions.py:794-797`).
- During redirects, each redirect hop's response is also saved to the session jar (`sessions.py:303`).

## 2. Attaching cookies to the next request

**Merge** (`sessions.py:524-533`)
- `Session.prepare_request` converts the per-request `cookies` dict to a jar if needed (`sessions.py:527-528`).
- It merges two jars into a fresh `RequestsCookieJar` with `merge_cookies(merge_cookies(RequestsCookieJar(), self.cookies), cookies)` (`sessions.py:531-533`). Session cookies go in first and per-request cookies are added after them.
- `merge_cookies` handles dicts and jars. For a jar it uses `update` where available, otherwise it copies cookie by cookie (`cookies.py:616-625`).

**Prepare** (`sessions.py:552`, `models.py:443`, `models.py:699-720`)
- The merged jar is passed as `cookies=merged_cookies` to `PreparedRequest.prepare` (`sessions.py:552`), which calls `prepare_cookies` (`models.py:443`).
- `prepare_cookies` keeps a jar as `self._cookies`, or builds one from a dict (`models.py:712-715`).
- It then calls `get_cookie_header(cookies_jar, self)` (`models.py:717-718`).
- A non-`None` result is set as the `Cookie` header (`models.py:719-720`).

**Header generation** (`cookies.py:153-161`)
- `get_cookie_header` wraps the prepared request in a `MockRequest` and runs `jar.add_cookie_header(r)` (`cookies.py:159-160`). The jar's domain, path, secure and expiry rules decide which cookies match the URL.
- The header the jar produces is stored in the `MockRequest`'s `_new_headers`, and `get_new_headers()` returns that dict (`cookies.py:98-99`, `cookies.py:161`).

## 3. Redirects (`sessions.py:260-269`)

On each redirect hop, `resolve_redirects`:
- drops the stale `Cookie` header (`sessions.py:261`);
- extracts the redirect response's cookies into the old request's jar, `prepared_request._cookies` (`sessions.py:266-267`);
- merges in `self.cookies` (`sessions.py:268`);
- calls `prepare_cookies` again for the new URL (`sessions.py:269`).

A cookie set by a redirect response is therefore sent on the following hop. Because the jar filters by domain and path, it is not sent to unrelated hosts.

I didn't see `MockRequest`'s other methods, `Response`'s other methods or `cookiejar_from_dict`. The domain, path and expiry filtering described here is standard `http.cookiejar` behavior, not something visible in these excerpts.

# Proxy selection in requests

Paths are under `src/requests/`. This is based on the supplied excerpts and the earlier ones in this conversation. I didn't re-read the files, and no files were modified.

## 1. Gathering candidates (normal `Session.request` path)

1. **Start with the caller's proxies.** `Session.request` uses `proxies or {}` (`sessions.py:639`).
2. **Add environment proxies.** `merge_environment_settings` (`sessions.py:831-868`) does this only when `self.trust_env` is true (`sessions.py:845`).
   - It reads a `no_proxy` entry from the caller's `proxies` dict, if any (`sessions.py:847`).
   - `get_environ_proxies(url, no_proxy=...)` returns `{}` if the URL should bypass proxies, otherwise `getproxies()` (`utils.py:873-882`). That is the standard-library reader of `*_proxy` environment variables.
   - Each environment entry is added with `setdefault`, so proxies passed explicitly to the call win (`sessions.py:849-851`).
3. **Merge with session proxies.** `merge_setting(proxies, self.proxies)` (`sessions.py:863`) combines the two dicts. The per-request value wins for a key present in both, and `None` values are dropped (`sessions.py:84-105`).
4. **Result.** The merged `proxies` dict is passed to `send` (`sessions.py:868`, `sessions.py:646-651`).
