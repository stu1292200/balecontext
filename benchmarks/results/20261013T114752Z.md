## Answer: run1-hook.answer.md

I added `--exclude` / `-x` to `listurls`, with docs, a release note and tests. Nothing was run, so the new tests and the docs build are untested.

**Command, `django/core/management/commands/listurls.py`**
- Lines 52-58 add the `--exclude` / `-x` argument. It takes one or more prefixes and is stored as `excluded_prefixes`.
- Lines 70-73 in `handle()` read the option and pass it to `get_url_patterns()`.
- Lines 95-98 give `get_url_patterns()` a new `excluded_prefixes=None` parameter and update its docstring.
- Lines 119-129 do the filtering. A route is skipped if `--prefix` is set and it matches none of the prefixes. It is also skipped if it starts with any excluded prefix. So `--prefix` keeps routes first and `--exclude` then drops from those.
- I kept the existing "There are no URL patterns that match given prefixes" error. It also fires when everything is excluded.

**Reference docs, `docs/ref/django-admin.txt`**
- Lines 538-543 add the `.. django-admin-option:: --exclude, -x [prefix ...]` entry, placed after `--prefix` and written like the neighbouring options. It explains that it is the opposite of `--prefix` and how the two combine.

**Release notes, `docs/releases/6.2.txt`**
- Lines 195-196 add a bullet under Management Commands in Minor features: "The new :option:`listurls --exclude` option hides URLs whose route starts with any of the given prefixes."

**Tests, `tests/admin_scripts/tests.py`** (in the `Listurls` class, after `test_prefixes`)
- `test_exclude` (line 3643) excludes `/namespaced` with `-x`.
- `test_exclude_multiple_prefixes` (line 3661) passes two prefixes to `--exclude`.
- `test_exclude_with_prefix` (line 3675) combines `-p` and `-x`.
- `test_exclude_all` (line 3691) uses the same prefix for both options and expects the "no URL patterns" error.

I assumed a `/cbv/named` route exists in `admin_scripts.app_with_urls`, based on the existing `test_cbv_formatting`. The multiple-prefix and `-p`/`-x` tests rely on it.
