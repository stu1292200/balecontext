## 1. Compile time: building the nodes

**`do_extends`** (`loader_tags.py:291-312`)

- It compiles the parent name as a filter expression, so it can be a literal or a variable (`:306`).
- `parser.parse()` consumes the rest of the template as the child's node list (`:307`).
- A second `extends` in the same template raises `TemplateSyntaxError` (`:308-311`).
- It returns `ExtendsNode(nodelist, parent_name)` (`:312`).

**`do_block`** (`loader_tags.py:214-243`)
- It requires one argument, the block name (`:221-224`).
- It tracks names already seen on the parser, so a duplicate block name in one template is an error (`:227-234`).
- It parses up to `endblock` (`:235`) and accepts `endblock` or `endblock <name>` (`:238-241`).
- It returns `BlockNode(block_name, nodelist)` (`:243`).

**`ExtendsNode.__init__`** (`loader_tags.py:90-94`) pre-computes `self.blocks`, a `{name: BlockNode}` dict of every `BlockNode` in the child's node list. It uses `get_nodes_by_type` (`:94`; `base.py:1110-1115`).

## 2. Render time: `ExtendsNode.render` (`loader_tags.py:134-160`)

1. **Locate the parent:** `get_parent(context)` (`:135`, defined at `:117-132`).
   - It resolves `parent_name` against the context (`:118`). An empty value raises `TemplateSyntaxError` (`:119-125`).
   - If the value is already a `Template`, or has a `.template` attribute that is one, it is used directly (`:126-131`).
   - Otherwise `find_template` runs (`:132`; `:99-115`).
2. **Recursion guard:** `find_template` keeps a `history` list of origins in `render_context` (`:106-109`). It passes it as `skip=` to `engine.find_template` (`:110-113`) and appends the new origin (`:114`).
   - This lets `{% extends "base.html" %}` inside an overriding `base.html` find the next template with the same name, instead of itself.
   - `Engine.find_template` (`engine.py:155-163`) tries each loader from `template_loaders` (`:129-131`, built by `get_template_loaders` at `:133-139`). It raises `TemplateDoesNotExist` with the collected `tried` list if none match.
3. **Create the `BlockContext`:** if `BLOCK_CONTEXT_KEY` isn't in `context.render_context`, a new `BlockContext` is stored there (`:137-139`; `BlockContext.__init__` at `:15-17` makes a `defaultdict(list)` of per-name queues).
4. **Register the child's blocks:** `block_context.add_blocks(self.blocks)` (`:142`). `add_blocks` does `insert(0, block)` per name (`:22-24`). The child's blocks go in first, and ancestors added later end up at the front.
5. **Register the root's blocks:** the loop at `:146-155` finds the parent's first non-text node.
   - If it is not an `ExtendsNode`, the parent is the root. All of its `BlockNode`s are collected and added to the block context (`:149-154`).
   - If it is an `ExtendsNode`, nothing is added here. That parent's own `render` registers its blocks when it runs, so the chain builds up level by level.
6. **Render the parent:** with `render_context.push_state(compiled_parent, isolated_context=False)` (`:159`, defined in `context.py:210-221`), it calls `compiled_parent._render(context)` (`:160`).
   - `_render` is just `self.nodelist.render(context)` (`base.py:166-167`).
   - `isolated_context=False` skips pushing a new render-context layer (`context.py:214-215`), so the `BlockContext` stays visible to the parent.
   - The code comment at `:157-158` says calling `_render` directly keeps the parser context the same.

## 3. Render time: `BlockNode.render` (`loader_tags.py:51-69`)

When the root template's nodes render, each `BlockNode` runs:

1. It reads `BLOCK_CONTEXT_KEY` from `render_context` (`:52`) and pushes a context layer (`:53`).
2. **No `BlockContext`** (the template is rendered standalone, not via `extends`): it sets `context["block"] = self` and renders its own nodelist (`:54-56`).
3. **With a `BlockContext`:**
   - `push = block = block_context.pop(self.name)` (`:58`). `pop` takes the last item of the name's list (`:26-30`), which is the most-derived override. It returns `None` if the list is empty.
   - If `block` is `None`, it falls back to `self` (`:59-60`).
   - It makes a fresh `BlockNode` copy, `type(self)(block.name, block.nodelist)` (`:63`). The code comment says this avoids thread-safety issues when storing `context` on it.
   - It sets `block.context = context` and `context["block"] = block` (`:64-65`), then renders the chosen block's nodelist (`:66`).
   - If something was popped, it pushes it back (`:67-68`), so the same block can render again if it appears elsewhere.

`NodeList.render` joins the rendered nodes into a `SafeString` (`base.py:1107-1108`).

## 4. `{{ block.super }}`: `BlockNode.super` (`loader_tags.py:71-83`)
- `context["block"]` is the copy that `render` created (`:65`), which has a `.context` attribute (`:64`).
- If `.context` is missing, `super` raises a `TemplateSyntaxError` that hints at using `block.super` in a base template (`:72-76`).
- If the `BlockContext` still has a block queued under this name, `get_block` returns non-`None` and `super` re-renders via `self.render(self.context)` (`:78-82`).
  - The overriding block was popped off the queue in `render`, so this render pops the next block up the chain (the parent's version).
  - The result is `mark_safe`d.
- Otherwise it returns `""` (`:83`).

## Render time

### `BlockContext` (`:14-39`)
It holds, for each block name, a list of `BlockNode`s. The list is ordered so that `.pop()` and `[-1]` give the most-derived override:
- `add_blocks` inserts at position 0 (`:22-24`).
- `pop` takes from the end (`:26-30`).
- `push` appends (`:32-33`).
- `get_block` peeks at the end (`:35-39`).

### `ExtendsNode.render` (`:134-160`)

This is how a template can extend another template with the same name, for example an overriding `admin/base.html` that extends the original one, without looping.
2. It creates a `BlockContext` in `render_context` if one doesn't exist yet (`:137-139`).
3. It calls `block_context.add_blocks(self.blocks)` (`:142`). These are this child's blocks. They are inserted at the front, so ancestors added later sit closer to the front and the child's blocks stay at the end, where `pop()` finds them first.

   - `_render` is `self.nodelist.render(context)` (`base.py:166-167`), called directly so the parser and template context stay the same (`:157-158`).
   - `isolated_context=False` keeps the `render_context`, and so the `BlockContext`, shared across levels. `push_state` is at `context.py:211`, and `RenderContext` at `context.py:179`.
   - The child's own text and non-block nodes are never rendered. Only its blocks matter.

### `BlockNode.render` (`:51-69`)
The root template's `BlockNode`s are the ones that run, and each decides what to output:
- It reads the `BlockContext` from `render_context` (`:52`).
- **No `BlockContext`** (the template is rendered on its own, with no `extends`): it renders its own `nodelist` with `context["block"] = self` (`:54-56`).
- **With a `BlockContext`** (`:57-68`):
  1. `block_context.pop(self.name)` takes the most-derived override (`:58`). If there isn't one, it falls back to `self` (`:59-60`).
  2. It builds a fresh `BlockNode` copy with `block.context = context` (`:63-64`). The comment at `:61-62` says this avoids thread-safety problems from storing per-render state on a shared node.
  3. It renders that copy's nodelist inside `context.push()` (`:53`, `:66`).
  4. It pushes the popped block back (`:67-68`), so other renders of the same name, such as `{{ block.super }}`, still see it.

### `{{ block.super }}`: `BlockNode.super` (`:71-83`)
- `context["block"]` is the copy from `:65`, so `{{ block.super }}` calls `.super()` on it.
- It raises `TemplateSyntaxError` if there is no `context` attribute, which happens when it is used in a base template (`:72-76`).
- If the `BlockContext` still holds a block under that name after the pop, it calls `self.render(self.context)` and returns the result as safe (`:78-82`). That render pops the next, less-derived block, which is the parent's version.
- Otherwise it returns an empty string (`:83`).

## Example: `child` extends `base`, and `base` has `{% block content %}`
1. `Template.render` (`base.py:169`) → `nodelist.render` → `NodeList.render` (`base.py:1107-1108`) calls `ExtendsNode.render`.
2. The `BlockContext` gets `{content: [base_block, child_block]}`. The child block is last because `add_blocks` inserts at the front (`:142`, then `:154`).
3. The parent template renders. At its `{% block content %}`, `BlockNode.render` pops `child_block`, renders it, and pushes it back.
4. If the child uses `{{ block.super }}`, it pops `base_block`, renders it, and pushes it back.
